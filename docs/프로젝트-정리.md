## 3. Supabase

### 테이블
`profiles` / `transactions` / `work_claims` / `fixed_costs` / `coupang_items` / `settings` / `events`

`transactions` 주요 칼럼:
```
kind(expense|income|transfer)  source  tx_date  tx_time  merchant
amount(청구액)  raw_amount(할인전)  benefit  category  subcategory
income_src  is_work  installment  bill_month  owner  memo  fingerprint(unique)
```

- **`fingerprint`** 가 중복 방지의 핵심. `insertTx` 는 `onConflict:'fingerprint', ignoreDuplicates:true`
- **`memo`** 는 사실상 태그 저장소로 쓰고 있음 ← 설계 부채
  - `[생활비]` / `[생활비제외]` — 예산 포함 강제
  - `[기안:2026-08]` — 업무비용 기안 연결
  - `FX:MYR:150.00 @347.52` — 외화 결제·적용환율 (`?` 붙으면 잠정)
  - `이용내역` 포함 여부로 명세서/이용내역 구분

### 마이그레이션 적용 순서
```
1. schema.sql
2. migration-owner.sql          owner 칼럼
3. migration-budget-sms.sql     생활비 예산 · sms
4. migration-sms-raw.sql        문자 원문 파싱 함수
5. migration-events.sql         경조사 캘린더
6. migration-fx.sql             외화 결제
7. migration-time.sql           tx_time (결제 시각)
8. migration-sms-v3.sql         문자 파서 (KB RCS 카드형 대응)
9. migration-sms-watch.sql      ★문자 감시: 파서를 ingest_sms_parse 로 이름 바꾸고 기록용 겉함수 + sms_log
```
**9번 적용 후 파서 본문은 `ingest_sms_parse`** 입니다. 문자 형식이 바뀌면 v3 파일 내용을 `ingest_sms_parse` 이름으로 고쳐 돌릴 것.
`ingest_sms_raw` 는 모든 수신(성공·스킵·실패·예외)을 `sms_log` 에 남기고 120일 지나면 지움.

### RLS
`*_select_all` (모두 읽기) + `tx_write_all` (가구 공동 편집).
`fixed_costs` 만 `fx_write_own` 으로 본인 것만 수정.

### ⚠️ 칼럼 추가 시 반드시
```sql
notify pgrst, 'reload schema';
```
DB와 PostgREST가 스키마 캐시를 따로 들고 있음. 이것 없으면 SQL Editor에선 보이는데
앱에서는 "그런 칼럼 없다"고 조용히 실패함. **이것 때문에 하루 날림.**

## 4. 데이터가 들어오는 3가지 경로

### ① 문자 자동 (실시간, 갤럭시)
```
카드 승인 문자 → MacroDroid "카드 알림 가계부"
  → HTTP POST (text/plain) → public.sms(text) → ingest_sms_raw()
  → transactions 에 source='sms' 로 저장
```
- MacroDroid 매크로 2개: `카드 알림 가계부`(알림 트리거, **ON**) / `카드문자 가계부`(SMS 트리거, OFF)
- 삼성카드가 RCS로 오면 SMS 트리거가 안 먹어서 **알림 트리거**를 씀
- 비밀키는 `settings` 테이블 `sms_secret`. 코드에 하드코딩 안 함
- 본문은 `text/plain` 으로 보냄 (JSON이면 줄바꿈에서 깨짐)

### ② 파일 업로드 (월 1회)
`더보기 → 명세서 업로드`. 드래그로 여러 개 동시 가능.

| 파일 | 파서 | 특징 |
|---|---|---|
| 삼성카드 **명세서**.xlsx | `parseSamsung` | 시트 `일시불/할부/해외이용`. **승인시각 없음**. 금액은 col9(원금, 할인 반영) |
| 삼성카드 **이용내역**.xlsx | `parseSamsungUsage` | 시트 `■국내이용내역/■해외이용내역`. **승인시각 있음** |
| KB국민카드 이용내역.xls | `parseCardUsage` | 헤더 이름으로 열 찾는 범용 파서. `이용\n시간` 줄바꿈 주의 |
| 기업은행 .xls | `parseIbk` | "거래용"(진짜 엑셀)과 "출력용"(실은 HTML) 둘 다 지원 |
| 현대카드 .pdf | `parsePdf` | pdf.js. y좌표로 줄 복원 |
| 쿠팡 CSV | `parseCoupang` | 북마클릿/확장으로 뽑은 주문내역 |

### ③ 수동 입력
`더보기 → 지출·수입 입력`. 외화 통화 선택하면 결제일 환율로 자동 환산.

## 5. 핵심 로직

### 분류 엔진 (`categorize.js`)
- `CATEGORIES` 19개. 앞 12개가 통계청 **12대 소비지출** (평균 비교용)
- `RULES` 정규식 배열 — **먼저 매치되는 것이 이김**. 순서가 중요
- `DICT` 정확한 가맹점명 매핑
- `normalizeMerchant()` — `컴포즈커피신사점` → `컴포즈커피`
- **AI·소프트웨어 구독은 `정보통신`이 아니라 `사업·투자`** (개인사업자 선투자라서. 본인 요청)

### 생활비 판정 (`isBudgetTx`)
```
[생활비제외] → false
[생활비]     → true
외화 결제     → false  (여행은 예산과 분리)
삼성카드      → false  (기본 '용돈')
그 외: BUDGET_SUBS/CATS 에 걸리거나 source가 sms·kb_card 면 true
```

### 외화 (`fxOf` / `resolveFx` / `fxRate`)
- memo의 `FX:통화:금액` 을 읽어 **결제일 환율**로 원화 환산
- 환율: `api.frankfurter.dev/v1/` → 실패시 jsDelivr currency-api → 최신환율
- 해외수수료 `FX_FEE = 1.002` 적용 (실제 명세서와 대조해 검증함)
- 당일 결제는 고시 전이라 잠정(`@1383.07?`) → 다음날 자동 재계산
- **현지통화가 KRW인 건**(Zoom·Meta 광고)은 환산 안 함

### 정기결제 탐지 (`analytics.detectSubs`)
같은 가맹점+금액을 **한 달 간격 사슬**로 묶음. 결제일(며칠)이 다르면 별개 구독으로 분리.
→ 전부 `Google (제미나이 등)` 29,000원인 구독 3개를 20일/26일/27일로 정확히 갈라냄.
월 단위 재배정 보정 패스가 들어 있음 (`modeDay`).

### 중복 제거 2종
| | 함수 | 기준 |
|---|---|---|
| 문자 ↔ 카드 | `dedupeSmsVsCard` | 날짜±3일 + 금액 + 가맹점 |
| 이용내역 ↔ 명세서 | `dedupeUsageVsStatement` | 같은 날·가맹점 + (`amount` **또는** `raw_amount`) 일치 |

**후자가 중요** — 명세서는 할인 반영 청구액, 이용내역은 승인금액이라 금액이 다름.
`raw_amount`(할인 전)도 같이 비교해야 97% 잡힘. 명세서 쪽을 남기고 시각만 옮겨붙임.

## 7. 겪은 함정 (다시 밟지 말 것)

### 한글 폴더 NFC/NFD
macOS는 한글 파일명을 **NFD(자모 분해형)** 로 저장. 샌드박스에서 NFC로 경로를 만들면
**보이지 않는 유령 폴더**가 생겨서 Finder/터미널에 안 보임.
→ 경로는 항상 `os.listdir()` 로 받아서 쓰고, 비교할 때만 `unicodedata.normalize('NFC', ...)`.
→ 지금도 마운트에 NFC 그림자 폴더가 하나 남아 있음(구버전 v23). **NFD 쪽이 진짜.**

### PostgREST 스키마 캐시
§3 참고. `alter table` 뒤에는 무조건 `notify pgrst, 'reload schema';`

### 서비스워커가 외부 API를 가로챔
fetch 핸들러가 모든 GET을 가로채서, 환율 API 요청이 실패하면 **`index.html`을 대신 돌려줌**.
JSON 파싱이 터지는데 원인이 안 보임. → `if (url.origin !== location.origin) return;` 로 해결.

### 텍스트 구간 치환으로 코드 날림
두 앵커 사이를 통째로 바꾸는 방식으로 함수를 수정하다가 그 사이에 있던 **필터 기능 100여 줄을 삭제**.
`FILT is not defined` 로 가계부·생활비·용돈 세 화면이 동시에 죽음.
→ 그래서 `tools/smoke.js` 와 `deploy.sh` 자가검사를 붙임. **편집 후 반드시 돌릴 것.**

### 조용한 실패
로딩 단계에 try/catch가 없어서 한 군데만 실패해도 통째로 빈 화면.
→ 지금은 `reload()` 각 단계와 `renderAll()` 의 화면별 렌더를 `safe()` 로 감싸고,
실패하면 화면 맨 위에 **노란 오류 박스**로 문구를 띄움. `window.onerror` 도 같은 박스로 보냄.
**오류를 삼키지 말 것.**

### 카드사 문자 형식이 계속 바뀜
- 삼성카드가 RCS(카톡 비슷한 형식)로 와서 SMS 트리거 안 먹음 → 알림 트리거로 변경
- KB가 RCS 카드형으로 바뀌어 **가맹점이 승인시각보다 위**로 올라감
→ 위치 기반 파싱을 버리고, **"라벨·금액·날짜가 아닌 첫 줄"** 을 가맹점으로 잡는 방식으로 전환.
6가지 실제 형식으로 검증함 (migration-sms-v3.sql).

### 카카오택시 가승인/취소
삼성 이용내역에 `가승인 +38,500` 과 `전체취소 −38,500` 이 짝으로 들어옴.
취소 건만 걸러내면 원승인이 남아 **15만원 넘게 부풀려짐**. → 승인번호로 짝지어 양쪽 다 제거.

### 삼성 해외 이용내역은 USD 기준

## 11. 개발 시 주의

1. **ES 모듈 쓰지 말 것.** `file://` 로도 열려야 해서 전역 `<script>` 방식 유지
2. **`app.js` 가 2,744줄.** 쪼개고 싶으면 `index.html` 의 script 순서와 전역 의존을 같이 봐야 함
3. **편집 후 `node tools/smoke.js`** 를 꼭 돌릴 것 (deploy.sh가 자동으로 하지만 수동 확인도)
4. **`sw.js` CACHE 버전 올리기**
5. **`memo` 태그 방식은 부채.** 칼럼으로 뺄 거면 마이그레이션 + 기존 데이터 변환 필요
6. **Supabase secret key 는 절대 코드에 넣지 말 것.** publishable key만 사용 (RLS로 보호)
7. 실제 파일로 테스트할 것. `~/Desktop/수입 지출 관리/` 에 실제 카드 파일들이 있음
